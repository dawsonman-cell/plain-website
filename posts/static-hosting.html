GitHub Pages 同靜態網站心得

用 GitHub Pages 發佈靜態站嘅實際流程同常見陷阱。

GitHub Pages 對純靜態站幾乎係「推上去就得」：倉庫開好、選好 source branch（常見係 main 根目錄），等一兩分鐘就有公開網址。對專案頁嚟講，網址會係 username.github.io/repo-name/，所以相對路徑要特別小心。

最常見嘅踩坑係鏈接寫死成根路徑（例如 /styles.css）。喺用戶站（user site）或者本地開檔可能冇問題，但喺專案頁底下就會 404。較穩陣嘅做法係用相對路徑：根目錄頁面寫 styles.css，子資料夾（例如 posts/）寫 ../styles.css，導航亦要用同一套邏輯。

另一個實際心得係：改完先本地用瀏覽器打開檢查導航同樣式，再 commit、push，然後用實際 Pages URL 驗證 HTTP 狀態，唔好假設「推咗就一定即時生效」。CDN 同建置隊列有時會有短暫延遲，稍等再試通常就會好。

免費、同 Git 工作流綁定、冇額外帳號——呢三點已經夠我繼續用 Pages 作為呢個示範站嘅正式發佈渠道。真正要動態功能時，再考慮其他服務不遲。
